# bili-agent 优化路线图

这份清单按“用户收益、稳定性和实施成本”排序。当前版本适合单机或单容器使用；涉及公网、多用户和大规模长视频时，应按阶段推进。

## P0：下一步优先处理

这些项目直接影响“能否稳定用”和“出错后能否恢复”。

1. **任务取消的深度打断**：让 yt-dlp、LLM 请求和 Whisper 转写共享取消令牌；当前取消会在阶段边界安全停止，正在执行的单次网络请求仍需自然返回。
2. **任务重试与退避**：针对 B 站限流、临时网络错误和 LLM 429 增加指数退避、最大重试次数和可重试错误分类。
3. **超时分层**：区分元数据、字幕、音频下载、ASR、视觉和 LLM 超时，并在 UI 中显示“可重试/不可重试”。
4. **分析幂等与断点续跑**：按视频、分P、配置指纹缓存阶段结果，重启或失败后只重跑缺失分P。
5. **磁盘配额与清理**：显示音频、视频、模型和 SQLite 占用；按 TTL、LRU 和最大容量清理缓存，防止磁盘被长视频耗尽。
6. **错误日志关联**：为每个任务增加 request ID/job ID，前端显示短错误码，日志保留完整 traceback，避免把内部异常直接返回用户。
7. **真实 API 集成测试**：增加可选的 B 站、yt-dlp 和 OpenAI 兼容服务 smoke test，默认关闭，通过 CI secret 手动触发。
8. **依赖锁定**：生成 `requirements.lock` 或 uv/pip-tools 锁文件，固定可复现的生产依赖版本。

## P1：产品体验

1. **实时日志抽屉**：显示当前分P、数据源、下载速度、ASR 已处理时长、LLM 重试和预计剩余时间。
2. **任务历史页**：按标题、时间、状态、来源和耗时筛选，支持恢复会话、重试失败任务和删除历史。
3. **分析预设**：快速切换“字幕优先”“无字幕极速 ASR”“图文视频”“高质量多模态”。
4. **质量面板**：展示每个分P的 CC/ASR/OCR/视觉覆盖率、语种、置信度和降级原因。
5. **章节跳转**：章节、证据、字幕时间戳点击后自动定位音频播放位置。
6. **问答引用交互**：引用来源可展开原文、播放片段并高亮命中的关键词。
7. **导出增强**：支持 Markdown、JSON、SRT/VTT、纯文本和 ZIP；文件名自动清理非法字符。
8. **一图流增强**：支持 PNG/PDF、主题选择、长图分页和中文字体回退。
9. **封面和媒体兼容**：增加备用封面源、WebP/AVIF 转换、失败重试和本地缩略图缓存。
10. **移动端操作**：优化分P选择、任务进度、音频播放和右侧详情抽屉。

## P1：内容质量

1. **分段切分优化**：按静音、标点、章节和语义边界合并字幕，减少 LLM 上下文断裂。
2. **跨分P去重**：合并重复片头、目录和知识点，保留原始分P引用。
3. **术语表与实体统一**：统一同义词、英文缩写、专有名词和人名译法。
4. **证据冲突检测**：标记字幕、OCR、视觉和元数据之间的矛盾，不强行合并。
5. **时间戳校准**：处理 ASR 偏移、分P全局时间和章节时间格式，提供相对/全局两种视图。
6. **语种混合识别**：按片段检测语言，而不是整段只使用一个语言；对中日英混说单独评估。
7. **音频事件识别**：识别音乐、掌声、爆音、静音和多人对话，为无语音视频补充信号。
8. **图文场景识别**：区分 PPT、代码、表格、演示操作、动漫画面和纯 B-roll，采用不同提示词。
9. **摘要可验证性**：每个章节和知识点关联至少一个证据时间段，降低幻觉。
10. **离线模型选择**：根据显存、CPU、时长和目标语言自动推荐 Whisper 模型和计算类型。

## P2：工程和安全

1. **迁移到 FastAPI/ASGI**：获得更标准的中间件、请求校验、OpenAPI、SSE/WebSocket 和优雅停机能力。
2. **队列与 Worker**：将 yt-dlp、ASR、OCR 和视觉任务移出 Web 进程，支持 Redis + RQ/Celery。
3. **多用户鉴权**：从单一 Bearer Token 升级为用户、项目、角色和配额。
4. **CSRF 与限流**：公网使用时加入 CSRF、IP/用户限流、并发配额和请求体限制。
5. **SSRF 防护**：继续限制封面代理域名；对所有远端 URL 做协议、重定向、DNS 和私网地址校验。
6. **密钥管理**：生产环境使用 Docker secrets、Vault 或云密钥服务，禁止通过 Web 面板保存公网生产 Key。
7. **结构化日志与指标**：输出 JSON 日志，记录耗时、成功率、缓存命中、token、带宽和错误分类。
8. **可观测性**：接入 Prometheus、OpenTelemetry、Sentry 或同类系统，设置 ASR/LLM 延迟告警。
9. **对象存储**：将 Markdown、JSON、媒体和一图流放入 S3 兼容存储，SQLite 只保留索引。
10. **数据库迁移**：多实例场景迁移 PostgreSQL，并实现 schema migration、备份和恢复演练。
11. **供应链安全**：锁定依赖、启用 Dependabot/Renovate、SBOM、镜像扫描和最小权限运行。
12. **内容合规**：增加版权提示、Cookie 使用说明、用户数据保留期限、删除接口和审计记录。

## P3：长期智能化

1. **多模态统一模型**：把字幕、音频事件、OCR、关键帧和元数据交给统一时序模型整合。
2. **检索增强问答**：使用向量索引、BM25 和时间邻域混合检索，替代单一关键词匹配。
3. **查询改写与多跳问答**：将模糊追问改写为可检索问题，再跨章节聚合证据。
4. **自动评测集**：按课程、访谈、游戏、新闻、音乐、无声图文、长视频建立基准集。
5. **质量评分**：以引用准确率、时间戳误差、摘要覆盖率、ASR WER 和用户反馈衡量版本质量。
6. **模型路由**：短视频使用小模型，长视频分块使用便宜模型，难题或视觉片段升级到强模型。
7. **主动澄清**：当证据不足或分P过多时，先询问用户目标、语言、质量和时间范围。
8. **知识库连接器**：导出或同步到 Obsidian、Notion、飞书、语雀、向量数据库和企业搜索。

## 推荐实施顺序

1. 先做 P0-1 至 P0-5，解决取消、重试、恢复和磁盘风险。
2. 再做 P1 的质量面板、章节跳转、引用播放和导出增强。
3. 需要公网多人使用时，优先做 P2 的鉴权、队列、限流、密钥和可观测性。
4. 最后建设评测集和多模态统一模型，用数据决定模型与提示词优化。
